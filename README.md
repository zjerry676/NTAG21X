# NTAG21x 工程笔记

这是一份面向嵌入式软硬件开发的 NTAG213、NTAG215 和 NTAG216 工程速查笔记。主要依据 NXP `NTAG213_215_216` 数据手册 Rev. 3.2，覆盖射频接口、内存组织、激活状态机、命令、安全配置和 NDEF 格式化。

## 使用建议

- 手机直接读写 URL、短文本、配对信息和普通标签类 NDEF：优先选择 NTAG21x。
- 根据 NDEF 最大长度选择型号：小消息优先 NTAG213，需要更大用户区时选择 NTAG215 或 NTAG216。
- 对新建的高安全场景，不要把密码保护或原创性签名当作完整的应用层安全方案；还需要后端校验、密钥管理和重放防护。
- 量产前必须使用目标天线、封装材料和读写器验证工作距离、写入寿命、功耗和 NDEF 兼容性。

##  存储器组织

NTAG21x 的 EEPROM 按页组织，每页固定 4 字节。根据数据手册第 8.5 节，NTAG213、NTAG215 和 NTAG216 的总页数分别为 45、135 和 231 页。内存区按功能分为制造商数据与静态锁定位、Capability Container（CC）、用户存储区、动态锁定位、配置页和保留字段；这种制造商数据、锁定位、CC 与用户页的结构与 NTAG203 兼容。

| 内存段 | NTAG213 | NTAG215 | NTAG216 | 用途 |
| --- | --- | --- | --- | --- |
| 制造商数据、静态锁定位 | `00h-02h` | `00h-02h` | `00h-02h` | UID、内部字节和不可随意改写的锁定位 |
| Capability Container | `03h` | `03h` | `03h` | 声明 Type 2 Tag 和 NDEF 区域 |
| 用户存储区 | `04h-27h` | `04h-81h` | `04h-E1h` | NDEF 和应用数据 |
| 动态锁定位 | `28h` | `82h` | `E2h` | 控制用户区后段的只读锁定 |
| 配置区 | `29h-2Ch` | `83h-86h` | `E3h-E6h` | `CFG0`、`CFG1`、`PWD`、`PACK` 和 RFU 字段 |

用户区末页之后的保留页不能按普通用户 RAM 使用。不同型号的锁定位数量也不同：NTAG213 为 34 bit，NTAG215 为 28 bit，NTAG216 为 37 bit；配置锁定前应根据实际型号读取并保存原始页内容。

### 容量和内存地图

| 型号 | EEPROM 总量 | 页数 | 用户区 | 用户页 | 动态锁页 | 配置页 |
| --- | ---: | ---: | ---: | --- | --- | --- |
| NTAG213 | 180 字节 | 45 页 | 144 字节 | `04h-27h` | `28h` | `29h-2Ch` |
| NTAG215 | 540 字节 | 135 页 | 504 字节 | `04h-81h` | `82h` | `83h-86h` |
| NTAG216 | 924 字节 | 231 页 | 888 字节 | `04h-E1h` | `E2h` | `E3h-E6h` |

每页为 4 字节。通用地图如下：

| 页 | 作用 |
| --- | --- |
| `00h` | 固定值，保留 |
| `01h` | UID 和内部字节的一部分 |
| `02h` | UID 余下部分、内部字节和静态锁定位 |
| `03h` | Capability Container（CC） |
| `04h` 起 | NDEF 和用户数据 |
| 用户区末页之后 | 动态锁定位、配置页和制造商保留区，具体页号随型号变化 |

CC 的默认值和 NDEF 区域声明：

| 型号 | Page `03h` 默认值 | CC 中的 NDEF 大小字段 | 备注 |
| --- | --- | --- | --- |
| NTAG213 | `E1 10 12 00` | `12h`，144 字节 | Page `04h` 默认 `01 03 A0 0C`，Page `05h` 默认 `34 03 00 FE` |
| NTAG215 | `E1 10 3E 00` | `3Eh`，496 字节 | Page `04h` 默认 `03 00 FE 00`，Page `05h` 全零 |
| NTAG216 | `E1 10 6D 00` | `6Dh`，872 字节 | Page `04h` 默认 `03 00 FE 00`，Page `05h` 全零 |

CC 的 NDEF 大小字段是格式化区域的声明值，不应与数据手册列出的整段用户 EEPROM 字节数混为一谈。写入 NDEF 时还要正确生成 TLV 的 `03h`（NDEF Message）和 `FEh`（终止符）。

## 射频和数据完整性

- 工作频率为 13.56 MHz，数据传输速率为 106 kbit/s。
- 射频接口符合 ISO/IEC 14443-A Type A；标签必须连接匹配的天线才能工作。
- 典型工作距离最高约 100 mm，实际值取决于场强、天线几何尺寸、匹配、封装材料和读写器。
- 输入电容典型值为 50 pF。天线设计应以目标封装和实际测量结果为准。
- 通信链路使用 16 位 CRC、每字节奇校验、bit count checking、bit coding 和 channel monitoring。
- 多标签场景使用抗碰撞流程逐个选中标签；不要在未完成选卡时直接读写用户页。

## 激活和状态机

NTAG21x 的状态机包括 `IDLE`、`READY1`、`READY2`、`ACTIVE`、`AUTHENTICATED` 和 `HALT`：

1. 上电复位后进入 `IDLE`。
2. 收到 `REQA (26h)` 或 `WUPA (52h)` 后进入寻卡流程。
3. 通过 `ANTICOLLISION CL1` / `SELECT CL1` 解析 UID 的第一级。
4. 对 7 字节 UID 继续执行 `ANTICOLLISION CL2` / `SELECT CL2`。
5. 收到最终 `SAK` 后进入 `ACTIVE`，可以执行内存和功能命令。
6. `PWD_AUTH` 成功后进入 `AUTHENTICATED`，可访问受密码保护的页。
7. 收到 `HLTA (50h 00h + CRC_A)` 后进入 `HALT`；只有 `WUPA` 能再次唤醒。

在 `IDLE`、`READY1`、`READY2`、`ACTIVE` 和 `AUTHENTICATED` 状态收到不符合当前状态的命令时，命令解释器会返回错误并回到适当的等待状态。驱动应为每个状态设置明确的超时和错误恢复路径。

## 常用命令

| 命令 | 码 | 数据阶段 | 说明 |
| --- | --- | --- | --- |
| `READ` | `30h` | 1 字节页号 | 从指定页开始返回连续 4 页，共 16 字节 |
| `WRITE` | `A2h` | 页号 + 4 字节 | 一次写一页，随后等待 ACK/NAK |
| `COMPATIBILITY_WRITE` | `A0h` | 页号 + 后续数据 | 兼容旧式写入时使用，按数据手册处理两阶段时序 |
| `FAST_READ` | `3Ah` | 起始页 + 结束页 | 连续读取页范围，帧长度随页数变化 |
| `GET_VERSION` | `60h` | 无 | 返回 8 字节产品版本信息 |
| `READ_CNT` | `39h` | 计数器编号 | 读取 NFC counter |
| `PWD_AUTH` | `1Bh` | 4 字节 PWD | 返回 2 字节 PACK；失败时按配置限制重试 |
| `READ_SIG` | `3Ch` | 无 | 读取 ECC 原创性签名 |

常见 ACK 为 4 位 `Ah`；NAK `0h`、`1h`、`4h`、`5h` 表示不同错误类别。实际驱动必须按 bit frame、CRC_A 和超时规则处理，而不是把返回值当作普通 8 位字节。

`READ` 的返回长度固定为 16 字节，但请求参数是页地址；不能把返回长度误认为地址单位。`FAST_READ` 不应越过有效地址，越界和受保护访问都要检查 NAK。

## 安全和配置

- `PWD` 为 32 位，`PACK` 为 16 位。
- `AUTH0` 指定从哪一页开始启用密码保护，`PROT` 决定保护读操作还是只保护写操作。
- `AUTHLIM` 可限制连续密码失败次数；超过限制后标签可能永久拒绝密码认证，必须谨慎配置。
- Page `02h` 的静态锁定位和动态锁页控制用户区是否可再写；锁定位通常是不可逆的。
- 配置页还包含 `CFGLCK`、`NFC_CNT_EN`、`NFC_CNT_PWD_PROT`、`MIRROR`、`MIRROR_PAGE` 和 `MIRROR_BYTE` 等字段。锁配置前应保留原始页内容并在样卡上验证。
- NTAG 的 ECC 签名适合做原创性校验；它不是应用层密钥协商或端到端保密机制。
- 数据手册给出的数据保持时间为 10 年，写入耐久度为 100,000 次量级；高频计数仍应设计磨损控制和掉电恢复策略。

## UID 和镜像

NTAG21x 的 UID 为厂家写入的固定 7 字节 UID。UID 由两级级联防碰撞流程解析，应用层应保留完整 7 字节值，不要只保存低 4 字节。

通过配置页可以把 UID 的 ASCII 表示或 NFC counter 的 ASCII 表示镜像到用户数据区：

- UID 镜像占 14 字节。
- counter 镜像占 6 字节。
- 联合镜像还包含分隔字符，总长度为 21 字节。
- 镜像位置由 `MIRROR_PAGE` 和 `MIRROR_BYTE` 指定，应用 TLV 长度必须同步调整。

镜像功能适合自动序列化标签或把读卡次数带入 NDEF，但不要把可读 UID 或计数器当作认证凭据。

## NDEF 写入流程

1. 完成 ISO/IEC 14443-A 激活和两级 UID 选卡。
2. 读取 Page `03h` 的 CC，确认 `E1h` magic number、版本和 NDEF 区域大小。
3. 在用户区 Page `04h` 起写入 TLV：`03h` + NDEF 长度 + NDEF Message + `FEh` 终止符。
4. 写入后回读并校验 TLV 长度、NDEF payload、CRC_A 和设备端解析结果。
5. 需要只读发布时，先在样卡上确认所有页内容，再写入静态或动态锁定位；锁定位通常不可逆。

写入跨多个页面时，应在每页写入后检查 ACK，并为掉电、移卡和超时保留可恢复路径。不要在未确认 CC 和用户页范围前批量写入。
