# NTAG21x 工程笔记

这是一份面向嵌入式软硬件开发的 NTAG213、NTAG215 和 NTAG216 工程速查笔记。主要依据 NXP `NTAG213_215_216` 数据手册 Rev. 3.2，覆盖射频接口、内存组织、激活状态机、命令、安全配置和 NDEF 格式化。

## 使用建议

- 手机直接读写 URL、短文本、配对信息和普通标签类 NDEF：优先选择 NTAG21x。
- 根据 NDEF 最大长度选择型号：小消息优先 NTAG213，需要更大用户区时选择 NTAG215 或 NTAG216。
- 对新建的高安全场景，不要把密码保护或原创性签名当作完整的应用层安全方案；还需要后端校验、密钥管理和重放防护。
- 量产前必须使用目标天线、封装材料和读写器验证工作距离、写入寿命、功耗和 NDEF 兼容性。

## 8.5 存储器组织

NTAG21x 的 EEPROM 按页组织，每页固定 4 字节。根据数据手册第 8.5 节，NTAG213、NTAG215 和 NTAG216 的总页数分别为 45、135 和 231 页。内存区按功能分为制造商数据与静态锁定位、Capability Container（CC）、用户存储区、动态锁定位、配置页和保留字段；这种制造商数据、锁定位、CC 与用户页的结构与 NTAG203 兼容。

| 内存段 | NTAG213 | NTAG215 | NTAG216 | 用途 |
| --- | --- | --- | --- | --- |
| 制造商数据、静态锁定位 | `00h-02h` | `00h-02h` | `00h-02h` | UID、内部字节和不可随意改写的锁定位 |
| Capability Container | `03h` | `03h` | `03h` | 声明 Type 2 Tag 和 NDEF 区域 |
| 用户存储区 | `04h-27h` | `04h-81h` | `04h-E1h` | NDEF 和应用数据 |
| 动态锁定位 | `28h` | `82h` | `E2h` | 控制用户区后段的只读锁定 |
| 配置区 | `29h-2Ch` | `83h-86h` | `E3h-E6h` | `CFG0`、`CFG1`、`PWD`、`PACK` 和 RFU 字段 |

用户区末页之后的保留页不能按普通用户 RAM 使用。不同型号的锁定位数量也不同：NTAG213 为 34 bit，NTAG215 为 28 bit，NTAG216 为 37 bit；配置锁定前应根据实际型号读取并保存原始页内容。

### 容量和内存地图

| 型号 | EEPROM 总量 | 页数 | 用户区 | 用户页 | 动态锁页 | 配置页 |
| --- | ---: | ---: | ---: | --- | --- | --- |
| NTAG213 | 180 字节 | 45 页 | 144 字节 | `04h-27h` | `28h` | `29h-2Ch` |
| NTAG215 | 540 字节 | 135 页 | 504 字节 | `04h-81h` | `82h` | `83h-86h` |
| NTAG216 | 924 字节 | 231 页 | 888 字节 | `04h-E1h` | `E2h` | `E3h-E6h` |

每页为 4 字节。通用地图如下：

| 页 | 作用 |
| --- | --- |
| `00h` | 固定值，保留 |
| `01h` | UID 和内部字节的一部分 |
| `02h` | UID 余下部分、内部字节和静态锁定位 |
| `03h` | Capability Container（CC） |
| `04h` 起 | NDEF 和用户数据 |
| 用户区末页之后 | 动态锁定位、配置页和制造商保留区，具体页号随型号变化 |

CC 的默认值和 NDEF 区域声明：

| 型号 | Page `03h` 默认值 | CC 中的 NDEF 大小字段 | 备注 |
| --- | --- | --- | --- |
| NTAG213 | `E1 10 12 00` | `12h`，144 字节 | Page `04h` 默认 `01 03 A0 0C`，Page `05h` 默认 `34 03 00 FE` |
| NTAG215 | `E1 10 3E 00` | `3Eh`，496 字节 | Page `04h` 默认 `03 00 FE 00`，Page `05h` 全零 |
| NTAG216 | `E1 10 6D 00` | `6Dh`，872 字节 | Page `04h` 默认 `03 00 FE 00`，Page `05h` 全零 |

CC 的 NDEF 大小字段是格式化区域的声明值，不应与数据手册列出的整段用户 EEPROM 字节数混为一谈。写入 NDEF 时还要正确生成 TLV 的 `03h`（NDEF Message）和 `FEh`（终止符）。

## 射频和数据完整性

- 工作频率为 13.56 MHz，数据传输速率为 106 kbit/s。
- 射频接口符合 ISO/IEC 14443-A Type A；标签必须连接匹配的天线才能工作。
- 典型工作距离最高约 100 mm，实际值取决于场强、天线几何尺寸、匹配、封装材料和读写器。
- 输入电容典型值为 50 pF。天线设计应以目标封装和实际测量结果为准。
- 通信链路使用 16 位 CRC、每字节奇校验、bit count checking、bit coding 和 channel monitoring。
- 多标签场景使用抗碰撞流程逐个选中标签；不要在未完成选卡时直接读写用户页。

## 激活和状态机

NTAG21x 的状态机包括 `IDLE`、`READY1`、`READY2`、`ACTIVE`、`AUTHENTICATED` 和 `HALT`：

1. 上电复位后进入 `IDLE`。
2. 收到 `REQA (26h)` 或 `WUPA (52h)` 后进入寻卡流程。
3. 通过 `ANTICOLLISION CL1` / `SELECT CL1` 解析 UID 的第一级。
4. 对 7 字节 UID 继续执行 `ANTICOLLISION CL2` / `SELECT CL2`。
5. 收到最终 `SAK` 后进入 `ACTIVE`，可以执行内存和功能命令。
6. `PWD_AUTH` 成功后进入 `AUTHENTICATED`，可访问受密码保护的页。
7. 收到 `HLTA (50h 00h + CRC_A)` 后进入 `HALT`；只有 `WUPA` 能再次唤醒。

在 `IDLE`、`READY1`、`READY2`、`ACTIVE` 和 `AUTHENTICATED` 状态收到不符合当前状态的命令时，命令解释器会返回错误并回到适当的等待状态。驱动应为每个状态设置明确的超时和错误恢复路径。

## 常用命令

| 命令 | 码 | 数据阶段 | 说明 |
| --- | --- | --- | --- |
| `READ` | `30h` | 1 字节页号 | 从指定页开始返回连续 4 页，共 16 字节 |
| `WRITE` | `A2h` | 页号 + 4 字节 | 一次写一页，随后等待 ACK/NAK |
| `COMPATIBILITY_WRITE` | `A0h` | 页号 + 后续数据 | 兼容旧式写入时使用，按数据手册处理两阶段时序 |
| `FAST_READ` | `3Ah` | 起始页 + 结束页 | 连续读取页范围，帧长度随页数变化 |
| `GET_VERSION` | `60h` | 无 | 返回 8 字节产品版本信息 |
| `READ_CNT` | `39h` | 固定计数器地址 `02h` | 读取 24 位 NFC 单向计数器 |
| `PWD_AUTH` | `1Bh` | 4 字节 PWD | 返回 2 字节 PACK；失败时按配置限制重试 |
| `READ_SIG` | `3Ch` | 无 | 读取 ECC 原创性签名 |

常见 ACK 为 4 位 `Ah`；NAK `0h`、`1h`、`4h`、`5h` 表示不同错误类别。实际驱动必须按 bit frame、CRC_A 和超时规则处理，而不是把返回值当作普通 8 位字节。

`READ` 的返回长度固定为 16 字节，但请求参数是页地址；不能把返回长度误认为地址单位。`FAST_READ` 不应越过有效地址，越界和受保护访问都要检查 NAK。

## 8.6 NFC 计数器

NTAG21x 的 NFC counter 是一个 24 位单向计数器。它可以被读取，也可以由芯片自动递增，但不能通过命令直接写入、减小或清零。达到 `FFFFFFh` 后，计数值不再变化。

### 先区分四个概念

| 配置或机制 | 控制的行为 | 不控制的行为 |
| --- | --- | --- |
| `NFC_CNT_EN` | 是否在每次射频上电后的第一次有效 `READ` 或 `FAST_READ` 时自动加一 | 不决定 `READ_CNT` 是否需要密码 |
| `NFC_CNT_PWD_PROT` | `READ_CNT` 和 NFC counter mirror 是否需要先完成 `PWD_AUTH` | 不负责启用计数器，也不决定何时加一 |
| `READ_CNT` | 返回当前 24 位计数值 | 不会触发计数器加一 |
| NFC counter mirror | 通过普通 `READ` 或 `FAST_READ` 返回 6 个 ASCII 十六进制字符 | 不是独立计数器，也不会额外加一 |

### 专用命令和递增条件

NTAG21x 只有一个计数器专用命令：`READ_CNT (39h)`。其参数不是可变编号，NTAG213、NTAG215 和 NTAG216 都使用固定 NFC counter 地址 `02h`：

```text
Request:  39 02 CRC_A
Response: Counter[3 bytes] CRC_A
```

`READ_CNT` 只读取当前值。计数器递增由另一个事件触发：

```text
NFC_CNT_EN = 1
        +
RF field power-on reset
        +
first valid READ or FAST_READ
        =
counter increments once
```

同一次射频上电期间继续执行 `READ` 或 `FAST_READ` 不会重复增加。`REQA`、选卡、`GET_VERSION` 和 `READ_CNT` 也不会替代这个触发条件。协议没有单独的 increment、write 或 reset counter 命令。

### 禁用计数器时的 `READ_CNT`

`NFC_CNT_EN = 0` 关闭的是自动递增，不是 `READ_CNT` 命令。数据手册没有单列 `NFC_CNT_EN = 0` 时的特殊响应；它分别定义 `NFC_CNT_EN` 负责递增、`READ_CNT` 返回当前值，并且只把“启用密码保护但尚未认证”列为该命令的保护性 NAK 条件。因此工程实现应按以下行为处理：

- 新标签的计数器通常保持在 `000000h`。
- 如果计数器已经增长，清除 `NFC_CNT_EN` 只会冻结现有值，不会清零。
- 未启用计数器密码保护时，`READ_CNT` 仍返回当前 3 字节值和 CRC_A。
- 启用 `NFC_CNT_PWD_PROT` 后，未认证时 `READ_CNT` 返回 NAK，认证成功后返回当前值。

| `NFC_CNT_EN` | `NFC_CNT_PWD_PROT` | 是否自动递增 | `READ_CNT` | Counter mirror |
| ---: | ---: | --- | --- | --- |
| `0` | `0` | 否 | 无需认证，返回冻结的当前值 | 不应依赖；数据手册要求 counter mirror 同时启用 `NFC_CNT_EN` |
| `0` | `1` | 否 | 认证前 NAK，认证后返回冻结的当前值 | 不应依赖；数据手册要求 counter mirror 同时启用 `NFC_CNT_EN` |
| `1` | `0` | 每次射频上电后首次有效 `READ` / `FAST_READ` 加一 | 无需认证，返回当前值 | 可配置为无需 counter 密码认证 |
| `1` | `1` | 每次射频上电后首次有效 `READ` / `FAST_READ` 加一 | 认证前 NAK，认证后返回当前值 | 仅在有效密码认证后镜像 counter |

### 除 `READ_CNT` 之外的读取方式

启用 NFC counter mirror 后，芯片会把 3 字节计数值转换成 6 个 ASCII 十六进制字符，并虚拟映射到用户区。配置要求包括：

- `NFC_CNT_EN = 1`。
- `MIRROR_CONF = 10b` 时只镜像 counter，`11b` 时镜像 UID 和 counter。
- `MIRROR_PAGE > 03h`，并确保 `MIRROR_PAGE`、`MIRROR_BYTE` 和所需长度不越过用户区边界。

例如计数值 `003F31h` 会被普通 `READ` 或 `FAST_READ` 读取为 ASCII 字符 `003F31`，对应字节 `30 30 33 46 33 31`。该内容是读取时生成的虚拟数据，不是 MCU 反复写入 EEPROM 的结果。

`NFC_CNT_PWD_PROT = 1` 同时保护 `READ_CNT` 和 counter mirror。设置为 `0` 时，`READ_CNT` 不需要密码；但 counter mirror 所在的用户页仍可能受到 `AUTH0 + PROT` 的页访问保护，这是独立的第二层访问条件。

## 安全和配置

- `PWD` 为 32 位，`PACK` 为 16 位。
- `AUTH0` 指定从哪一页开始启用密码保护，`PROT` 决定保护读操作还是只保护写操作。
- `AUTHLIM` 可限制连续密码失败次数；超过限制后标签可能永久拒绝密码认证，必须谨慎配置。
- Page `02h` 的静态锁定位和动态锁页控制用户区是否可再写；锁定位通常是不可逆的。
- 配置页还包含 `CFGLCK`、`NFC_CNT_EN`、`NFC_CNT_PWD_PROT`、`MIRROR`、`MIRROR_PAGE` 和 `MIRROR_BYTE` 等字段。锁配置前应保留原始页内容并在样卡上验证。
- NTAG 的 ECC 签名适合做原创性校验；它不是应用层密钥协商或端到端保密机制。
- 数据手册给出的数据保持时间为 10 年，写入耐久度为 100,000 次量级；高频计数仍应设计磨损控制和掉电恢复策略。

## 8.7 ASCII 镜像功能

NTAG21x 可以把 UID 和 NFC counter 以 ASCII 十六进制字符的形式，虚拟映射到用户存储区。读取相关页时，`READ` 或 `FAST_READ` 返回的是包含镜像内容的虚拟内存，不需要 MCU 每次重新写入 EEPROM。

### 能解决什么问题

批量生产时，可以先把所有标签写成同一个 NDEF 模板，再由芯片在读取时自动填入每张标签自己的 UID 或 counter。例如，物理内存预先写入：

```text
https://example.com/tag?id=00000000000000
```

开启 UID 镜像后，手机实际读到的 URL 可以变成：

```text
https://example.com/tag?id=04E141124C2880
```

这样可以用同一份 NDEF 模板完成标签自动序列化，减少逐卡写入和生产线数据准备工作。counter 镜像还可以把标签被读取的次数带入 URL 或文本，便于轻量统计。

### 镜像类型和占用空间

| 类型 | 输出内容 | 需要预留的用户区空间 | 常见用途 |
| --- | --- | ---: | --- |
| UID 镜像 | 7 字节 UID 转为 14 个 ASCII 字符 | 14 字节 | 标签序列号、唯一 URL、产品追踪 |
| NFC counter 镜像 | 3 字节 counter 转为 6 个 ASCII 字符 | 6 字节 | 统计读取次数 |
| UID + counter | 14 字节 UID + 1 字节 `x` + 6 字节 counter | 21 字节 | 同时识别标签和统计读取次数 |

联合镜像示例：

```text
https://example.com/tag?id=04E141124C2880x003F31
```

其中 `x` 是芯片自动插入的分隔字符（ASCII `78h`）。如果镜像区域越过用户存储区边界，芯片不会执行镜像。

### 配置和计数规则

- `MIRROR_PAGE` 大于 `03h` 时启用镜像，并指定镜像起始页。
- `MIRROR_BYTE` 指定起始页内的字节偏移。
- `MIRROR_CONF` 为 `00b` 时关闭，`01b` 选择 UID，`10b` 选择 NFC counter，`11b` 同时选择两者。
- NFC counter 为 24 bit；启用 `NFC_CNT_EN` 后，在每次射频上电后的第一次有效 `READ` 或 `FAST_READ` 时递增。
- counter 达到 `FFFFFFh` 后停止变化；读取 counter 也可以按配置要求先完成密码认证。
- 镜像占用的是 NDEF 用户区中的预留位置，NDEF 的 TLV 长度必须按最终镜像长度计算。

### 安全边界

ASCII 镜像适合自动编号和轻量统计，不是认证机制：

- UID 通常可以被读取，不是秘密。
- counter 只能反映芯片记录的读取次数，不能证明请求来自真实标签。
- 更换或复制标签后，后端不能只凭 UID 或 URL 参数判断真伪。
- 不要把镜像内容直接当作授权凭据；需要防伪时，应增加密码学认证、后端校验和重放防护。

## 8.8 密码验证保护

密码验证保护是访问控制，不是 EEPROM 加密。它通过 `AUTH0` 指定一段连续的受保护页，再由 `PROT` 决定这些页需要密码才能写入，还是读写都需要密码。密码验证成功后，标签进入 `AUTHENTICATED` 状态；但已经被静态或动态锁定位设置为只读的页面，仍然不能写入。

### 配置页布局

| 配置项 | NTAG213 | NTAG215 | NTAG216 | 说明 |
| --- | --- | --- | --- | --- |
| `AUTH0` | `29h` | `83h` | `E3h` | 所在页的 Byte 3 定义密码保护起始页 |
| `ACCESS` | `2Ah` | `84h` | `E4h` | Byte 0 包含 `PROT`、`CFGLCK`、`AUTHLIM` 等字段 |
| `PWD` | `2Bh` | `85h` | `E5h` | 4 字节密码，低字节在前 |
| `PACK` | `2Ch` | `86h` | `E6h` | 2 字节密码应答值，低字节在前 |

这些配置页位于动态锁定位之后。不同型号只改变页地址，字段语义相同。默认 `AUTH0 = FFh`，表示密码保护关闭；默认 `PWD = FFFFFFFFh`、`PACK = 0000h`，量产时必须修改默认值。

### `AUTH0`：保护范围

`AUTH0` 是第一个需要密码验证的页，保护范围为从该页一直到芯片最后一个有效配置页：

```text
AUTH0 <= page <= last_page
```

例如 NTAG213 设置 `AUTH0 = 04h`，表示从 Page `04h` 开始的用户区和后续配置区进入密码保护范围。`AUTH0 = FFh` 或设置为大于最后有效页的值时，密码保护等效关闭。

`AUTH0` 不是密码，也没有单独的结束地址。设置起始页时必须确认是否会同时覆盖动态锁定位页和配置页，否则后续写入这些页可能需要先执行 `PWD_AUTH`。

### `PROT`：写保护或读写保护

`PROT` 位于 `ACCESS` 字节的 bit 7：

- `PROT = 0`：从 `AUTH0` 开始只保护写操作，未认证时仍可读取。
- `PROT = 1`：从 `AUTH0` 开始读取和写入都需要密码。

密码保护只对尚未被其他机制锁死的页面产生放行作用。页面已经被 `Lx` 锁定后，即使 `PROT = 0` 或认证成功，也只能读取，不能重新写入。

### `PWD`、`PACK` 和 `PWD_AUTH`

配置表中的 `PWD 32 FFFFFFFFh` 和 `PACK 16 0000h` 分别表示字段名称、位宽和默认值：

| 字段 | 位宽 | 出厂默认值 | 作用 |
| --- | ---: | --- | --- |
| `PWD` | 32 bit，4 字节 | `FFFFFFFFh` | 实际参与比较的秘密密码 |
| `PACK` | 16 bit，2 字节 | `0000h` | 密码正确后返回的确认值 |

因此 `PACK` 不是“16 位密码”，也不是根据 `PWD` 计算出的哈希或 MAC。`16` 只是字段宽度，`0000h` 是出厂默认值。量产时应同时配置非默认的 `PWD` 和 `PACK`，读写器还必须比较返回的 `PACK` 是否等于该标签的预期值。

密码验证使用 `PWD_AUTH (1Bh)` 命令：

```text
Request:  1B PWD[4 bytes] CRC_A
Success:  PACK[2 bytes] CRC_A
Failure:  NAK or timeout
```

1. NFC 设备发送命令码 `1Bh` 和 4 字节 `PWD`。
2. 密码正确时，标签返回 2 字节 `PACK`，并进入 `AUTHENTICATED` 状态。
3. 在该状态下，可以访问由 `AUTH0` 和 `PROT` 保护、且尚未被锁定位锁死的页面。
4. 执行 `HLTA`、掉场或复位后，认证状态失效，下次会话需要重新认证。

`PWD` 和 `PACK` 在配置页以及 `PWD_AUTH` 命令和响应中均按低字节优先排列。例如数值 `PACK = 1234h` 的字节顺序为 `34 12`。两者的真实内容永远不能通过 `READ` 或 `FAST_READ` 读出，读取对应页面时标签返回 `00h` 字节；因此读到 `00 00` 不能证明实际 `PACK` 就是 `0000h`。仅写入 `PWD` 和 `PACK` 也不会自动启用保护，必须继续配置 `AUTH0`。

### `AUTHLIM`：限制错误认证次数

`AUTHLIM` 用于限制连续错误的密码验证次数：

- `000b`：不限制错误次数。
- `001b` 到 `111b`：最多允许 1 到 7 次错误验证。
- 达到上限后，后续 `PWD_AUTH` 永久失败，不论之后提交的密码是否正确。
- 在达到上限前认证成功，会将错误计数清零。

达到上限后，永久失效的是 `PROT` 指定的访问类型，而不是一定让整颗标签失效。例如 `PROT = 0` 时，可能只永久禁止受保护区域写入；`PROT = 1` 时，读写都会被永久禁止。因此 `AUTHLIM` 能限制暴力尝试，但错误配置也会造成拒绝服务。

### `CFGLCK`：锁住访问配置

`CFGLCK` 位于 `ACCESS` 字节的 bit 6。设置后，前两个配置页的写入会被永久禁止，主要包括 `AUTH0` 和 `ACCESS`；该锁定效果在下一次上电复位后生效。`PWD` 和 `PACK` 页是例外，仍保留写入能力；如果它们落在 `AUTH0` 保护范围内，写入时仍需先认证。因此不能只依赖 `CFGLCK` 保护密码本身。

推荐在写入新密码后，将 `AUTH0` 设置为 `PWD` 所在页：NTAG213 为 `2Bh`，NTAG215 为 `85h`，NTAG216 为 `E5h`。这样未经认证的设备不能改写 `PWD` 和 `PACK`，同时再使用 `CFGLCK` 固化 `AUTH0` 和 `ACCESS`。

### 与静态、动态锁定位的关系

一次写入是否成功，需要同时满足两个条件：

1. 目标页没有被静态或动态锁定位设置为只读。
2. 如果目标页地址大于等于 `AUTH0`，则当前会话已经通过 `PWD_AUTH`。

可以概括为：

```text
write_allowed = page_not_locked AND (page < AUTH0 OR authenticated)
```

访问效果如下：

| 页面状态 | 未认证 | 已认证 |
| --- | --- | --- |
| `page < AUTH0`，且未被锁定 | 按普通规则访问 | 按普通规则访问 |
| `page >= AUTH0`，`PROT = 0` | 可读，不可写 | 可读写 |
| `page >= AUTH0`，`PROT = 1` | 不可读写 | 可读写 |
| 已设置静态或动态锁定位 | 读取权限仍由 `PROT` 决定 | 仍然不可写 |

静态锁定位固定在 Page `02h`，动态锁定位位于 NTAG213 的 Page `28h`、NTAG215 的 Page `82h`、NTAG216 的 Page `E2h`。例如 NTAG213 设置 `AUTH0 = 04h` 时，动态锁定位页 `28h` 在密码保护范围内，而静态锁定位页 `02h` 低于该阈值；不能只根据用户区是否受保护来判断锁定位页的写入条件。

`READ`、`FAST_READ`、`WRITE` 和 `COMPATIBILITY_WRITE` 都要遵循上述访问规则。未认证时，`FAST_READ` 请求中只要包含 `AUTH0` 或之后的页面就会被拒绝；认证成功后，读取行为恢复正常，但锁定页仍不能写入。

### 推荐配置流程

1. 写入并回读验证最终的 NDEF 和用户数据。
2. 写入非默认的 `PWD` 和 `PACK`；此时尚未启用密码保护。
3. 配置 `AUTH0`、`PROT` 和 `AUTHLIM`，根据需要设置 `CFGLCK`。
4. 掉场或上电复位后，分别测试未认证和已认证时的读写行为。
5. 确认密码和配置备份无误后，再设置静态或动态锁定位。

锁定位和 `CFGLCK` 都可能造成永久性结果，必须在样卡上完成验证后再用于量产。密码保护只限制存储器访问，不提供加密传输或抗复制能力；高安全场景仍需要应用层密码学、后端校验和重放防护。

## NDEF 写入流程

1. 完成 ISO/IEC 14443-A 激活和两级 UID 选卡。
2. 读取 Page `03h` 的 CC，确认 `E1h` magic number、版本和 NDEF 区域大小。
3. 在用户区 Page `04h` 起写入 TLV：`03h` + NDEF 长度 + NDEF Message + `FEh` 终止符。
4. 写入后回读并校验 TLV 长度、NDEF payload、CRC_A 和设备端解析结果。
5. 需要只读发布时，先在样卡上确认所有页内容，再写入静态或动态锁定位；锁定位通常不可逆。

写入跨多个页面时，应在每页写入后检查 ACK，并为掉电、移卡和超时保留可恢复路径。不要在未确认 CC 和用户页范围前批量写入。
